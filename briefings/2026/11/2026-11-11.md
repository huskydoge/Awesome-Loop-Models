# Daily Loop-Model Briefing - 2026-11-11

## Outcome

One paper was added. It is a systems-and-architecture paper on serving looped language
models: it asks where a loop should sit in a causal encoder-decoder, whose few encoder layers
produce all global KV, and how to train the loop so that extra rounds add no KV cache. It cites
Benhao Huang's *Towards Looped Models Done Right*: Part I supports its choice of a looped middle
core over looping the whole stack, and Part II (*Rethinking at Fixed Points*) is the fixed-point
analysis it builds on for sharing the last round's KV across rounds.

## Added

### Looping Deeper Without Growing the KV Cache: Recurrent Depth for Causal Encoder-Decoders

[arXiv:2611.13378](https://arxiv.org/abs/2611.13378) · Code: none stated in the paper

**TL;DR:** Looped CED loops the encoder of a causal encoder-decoder and trains it with random
loop counts, so the loop converges and inference keeps only the last round's KV. It matches a
looped dense Transformer's quality with one-sixth of the global KV, and on a 552B-parameter
backbone it fits as many long requests as the unlooped model.

- **Setup:** 12-layer causal encoder-decoder (CED) models in the style of
  DeepSeek-V4.1-Flash, with a 128-token sliding window in every layer and global KV only from
  one encoder layer and one shared decoder projection. Models of about 90M, 150M and 340M
  non-embedding parameters are trained from scratch on FineWeb-Edu at 40 tokens per parameter,
  plus a 29.6B-token run at 150M. Baselines are an unlooped CED, a decoder-looped CED, and
  unlooped and looped dense Transformers with the same parameters and tokens.
- **Mechanism / Method:** A weight-tied 4-layer core (layers 2-5) is looped for 8 rounds
  between a prelude and a coda, with Parcae-style gated input injection. The core sits in the
  encoder, so each round refines the global KV source. Training samples the loop count per
  sequence from a Poisson distribution. This drives the core to a contractive fixed point, so at
  inference later tokens can attend to the last round's KV of earlier tokens and intermediate
  rounds are discarded.
- **Results:** The encoder loop matches looped dense validation BPB within 0.001 at all three
  scales and recovers 89%, 86% and 93% of the dense loop's gain with one-sixth of its global KV.
  A decoder loop with the same parameters and decode compute recovers only 16-40% of the
  encoder loop's gain. The encoder loop raises DCLM CORE by 2.54 points. A variant that loops
  only sliding-window layers (YOCO-U) fails to improve beyond the window on long documents. A
  fixed-depth loop instead falls into a period-4 limit cycle, so last-round KV no longer
  matches earlier rounds. Looping the 552B DeepSeek-V4.1-Flash for 8 rounds on one 4xGB200
  node, per-round KV cannot fit a single 128K-token request, while Looped CED stores 36.8x less
  KV per token, fits 38 such requests and serves 3.6x higher throughput on 8K-token prompts.
- **Caveat:** Quality results stop at 340M parameters and a 2048-token context. The 552B
  serving runs measure cost only, with weights that were not trained to loop, and they assume
  lossless last-round KV from the small models. Each round re-runs the core over the prompt, so
  the encoder loop costs more prefill compute than a decoder loop on prompt-heavy workloads.
- **Why added:** A shared 4-layer core is applied repeatedly within one forward pass. The
  paper's contribution is where to loop and how to cache KV across loop rounds.
- **Cites Benhao's work:** Cites *Towards Looped Models Done Right, Part I* in its background as
  evidence that looping a middle core beats looping the whole stack. It builds on *Part II:
  Rethinking at Fixed Points* (arXiv:2610.06833) throughout, citing it for stochastic-depth
  training, for terminal (last-round) KV sharing, for the collapse of fixed-depth loops under
  shared KV, and for Ouro's states not reaching a fixed point.
