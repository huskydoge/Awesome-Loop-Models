# Daily Loop-Model Briefing - 2026-11-22

## Outcome

Five papers were added. Two bring looped computation to vision-language models from opposite
directions: RecurrentVLM folds depth into time so that each attention layer carries a state
across video frame groups, and FoldCache cuts the decoding memory that weight-tied depth costs
in an existing looped VLM. LoopedWAM shows that a robot world action model can store 12 blocks
per expert instead of 30 and still match models ten times its size. dLoop retrofits a
recurrent middle block into a pretrained diffusion language model, and PSTO uses a reused
transport block as a finite fixed-point solver inside a physics surrogate. None of today's
additions cites Benhao Huang's work.

## Added

### Recurrent Vision Language Models Solve the Shell Game

[arXiv:2611.25210](https://arxiv.org/abs/2611.25210) · Code: not yet released (the authors
say it will be)

**TL;DR:** RecurrentVLM makes every attention layer of Qwen3.5-4B recompute the keys and values
of finished frame groups from its own output, so its state updates once per frame group, and
it tracks a ball through 50-swap shell games with 99% accuracy after training on at most 30.

- **Setup:** VET-Bench (cups and cards, 5 swaps) and MET-Bench (shell games, 10 swaps), plus
  longer games with 16 cup swaps and 30-100 shell swaps; three options, 33.3% chance. Built on
  Qwen3.5-4B (24 Gated DeltaNet layers and 8 attention layers), trained with LoRA on 4 RTX
  A5000 GPUs, and compared with a baseline fine-tuned on the same data and losses.
- **Mechanism / Method:** Following the Recurrent Transformer, once a frame group (two frames)
  ends, each attention layer recomputes that group's keys and values from its own output with
  the same projections. Later groups attend to this recurrent cache, so the number of state
  transitions grows with the video rather than with depth, while tokens within a group stay
  parallel. A frame-wise loss asks for the ball's position after every group.
- **Results:** 100% on VET-Bench and 99.6% on MET-Bench with one answer token, and 91% on Cup 16
  and 99% on Shell 50, against 37% and 38% for the fine-tuned baseline. Trained on up to 30
  swaps, it scores 98%, 99% and 84% at 30, 50 and 100 swaps. Running the model twice as a
  looped Transformer reaches only 57.4% on MET-Bench. Linear probes read the ball after the
  fourth attention layer at every swap, whereas the baseline needs one more attention layer
  about every two swaps.
- **Caveat:** Evaluated on synthetic shell-game benchmarks only; training costs 2.5x the
  baseline per step.
- **Why added:** Each attention layer feeds a state it computed back through the same layer
  for the next frame group, which is depth folded into time.

### Fold the Loop: Decoding-Time KV Memory for Looped Vision-Language Models

[arXiv:2611.25369](https://arxiv.org/abs/2611.25369) · Code: not stated in the paper

**TL;DR:** FoldCache keeps an exact prefill but lets groups of recurrent invocations of the same
weight-tied module share one visual KV copy during decoding, storing about half of LoopVL's
prefix cache at full-cache accuracy.

- **Setup:** LoopVL-1B, which runs two weight-tied 16-layer modules for 8 invocations (128
  layer executions from 32 layers of parameters), on ChartQA, MathVision, DocVQA, InfoVQA and
  TextVQA. Baselines include H2O and SnapKV eviction, Ouro- and Huginn-style cross-step KV
  sharing, MiniCache, KIVI and FlashLoop quantization.
- **Mechanism / Method:** Invocation-level ablations show that prefill must stay exact, that
  KV cannot be shared across different modules, and that decoding mostly reads each module's
  last invocation. FoldCache therefore groups the invocations of each module and lets each
  group's members read that group's final visual KV, while question and answer KV stay
  separate per invocation. FoldCache-Lite keeps one copy per module.
- **Results:** The default setting keeps 4 of 8 visual KV copies and stays within 0.02 points
  of the full cache on average. FoldCache-Lite stores 27% of the prefix KV and loses 0.90
  points on TextVQA. Ouro-style last-step sharing loses 19-46 points. In the same memory, batches
  grow 1.4-1.7x (1.9-2.6x for Lite) with up to 1.25x (1.37x) throughput.
- **Caveat:** Tested on one looped VLM, the only one with public weights; text-dense images
  are more sensitive to the aggressive setting.
- **Why added:** A systems method for the per-invocation KV caches created by reusing
  weight-tied modules within one forward pass.

### LoopedWAM: Looped World Action Models for Elastic Inference

[arXiv:2611.25595](https://arxiv.org/abs/2611.25595) · Code:
[anhdao69/LoopedWAM](https://github.com/anhdao69/LoopedWAM)

**TL;DR:** LoopedWAM stores 12 blocks per expert and loops a shared 6-block core to the 30-layer
depth of its donor, giving a 0.58B robot policy that reaches 96.1% on LIBERO and 91.9% on
RoboTwin 2.0.

- **Setup:** A world action model with a video expert and an action expert initialized from a
  Wan2.1 video diffusion transformer, evaluated on LIBERO, RoboTwin 2.0, RoboCasa-GR1 and four
  tasks on a real AgileX PiPER arm, without robot pretraining.
- **Mechanism / Method:** Each expert is a 3-block prelude, a 6-block core looped four times
  and a 3-block coda, with no input injection or loop embedding. Video loops run once per
  query and action loops at every sampling step, so the two depths are set separately and the
  last action loop attends to the deepest video loop. Elastic self-distillation trains one
  checkpoint, LoopedWAM-E, across action-loop and sampling-step budgets.
- **Results:** 96.1% on LIBERO, 91.9% on RoboTwin 2.0 (on par with the 6B Fast-WAM at 91.8%)
  and 52.2% on RoboCasa-GR1. LoopedWAM-E spans 24.7-86.2 ms per LIBERO query on an H100 at
  95.2-96.2% success. In ablations on a shorter training schedule, the looped model averages 94.9% on LIBERO against 90.0% for
  a 12-block untied model and 95.6% for a 30-block untied model with 1.42B parameters. On the
  real robot it succeeds in 57 of 80 trials, like Fast-WAM, with 3.7 GB instead of 12.7 GB.
- **Caveat:** Gains over the 30-block untied model come from parameters and memory, not
  accuracy; partition ablations mix partition and donor-block choice.
- **Why added:** A shared core block is applied repeatedly within each expert's forward pass,
  with depth chosen at test time.

### dLoop: Looped Diffusion Language Models via Recurrent Latent Refinement

[arXiv:2611.26275](https://arxiv.org/abs/2611.26275) · Code: not stated in the paper

**TL;DR:** dLoop splits LLaDA into a prelude, a shared loop block and a coda and reruns the loop
block inside each denoising step before tokens are committed, raising accuracy without a
confidence-forcing loss.

- **Setup:** LLaDA on GSM8K, MATH, MBPP and HumanEval, compared with native LLaDA, Fast-dLLM,
  dParallel and d3LLM using accuracy and tokens per forward pass (TPF) adjusted for the extra
  layers executed.
- **Mechanism / Method:** Layers 0-15 form the prelude, layers 16-21 the loop block and layers
  22-31 the coda. Extra loops reapply the block to the same partially masked state with a
  stable input-injection update borrowed from Parcae. Multi-depth SFT trains 0-3 extra loops,
  and a confidence-aware decoder commits tokens within a moving window.
- **Results:** GSM8K rises from 74.98% with no extra loop to 79.15% with two, and MATH from
  25.37% to 27.37%. dLoop has the highest or tied-highest accuracy on all four benchmarks; it
  beats Fast-dLLM on both accuracy and adjusted TPF everywhere and dParallel on three
  benchmarks, while d3LLM keeps higher TPF. Measured step times match the adjusted-TPF
  assumption within 3.4%.
- **Caveat:** Accuracy stops improving beyond two extra loops, and the main table's speed
  claims rely on the adjusted TPF metric.
- **Why added:** A parameter-shared block of layers is reused inside each forward pass of the
  denoiser.

### PSTO: A PDE-structured transport operator with shared implicit updates for multiscale CDR systems

[arXiv:2611.25607](https://arxiv.org/abs/2611.25607) · Code:
[kevin-sjtu/PSTO](https://github.com/kevin-sjtu/PSTO)

**TL;DR:** PSTO learns convection-diffusion from reaction-free data with one transport block
that it applies for a fixed number of relaxed fixed-point iterations, approximating an implicit
step and halving long-rollout error against the best neural baseline.

- **Setup:** A canonical 2D convection-diffusion-reaction system, a Robertson counterflow flame
  and a hydrogen planar jet flame, coupled to a separate reaction model by operator splitting
  and compared with neural transport surrogates and OpenFOAM.
- **Mechanism / Method:** Each variable is lifted to a latent state, updated by a shared
  advection-diffusion block (spectral and local convolutions) over K relaxed fixed-point
  iterations, and projected back to a physical increment. The paper proves convergence
  conditions and error bounds for the relaxed update.
- **Results:** With trained weights fixed, going from one to four iterations reduces the
  median one-step error 5.8x. After 100 coupled steps, mean relative error falls by at least
  50% against the best neural baseline in every case, accuracy holds at a tenfold larger time
  step, and the planar jet flame runs about 149x faster than OpenFOAM on 128 CPU ranks.
- **Caveat:** Two-dimensional cases and 100-step horizons only; the loop is a fixed four
  iterations rather than a converged solve.
- **Why added:** A learned block is reused for several fixed-point iterations within one
  forward step of the surrogate.

## Near misses

- **GLiDE: A Fast, Calibrated Decision Model Distilled from Reasoning Teachers**
  ([2611.26509](https://arxiv.org/abs/2611.26509)): applies two middle blocks of the final 27B
  model twice at inference without training, but this is a small add-on to a paper about
  distilling reasoning into single-pass decision models, and its gain is mixed with checkpoint
  averaging.
- **Efficient Latent Reasoning for Vision-Language Model via Dynamics-Aware Quantization and
  Distillation** ([2611.25670](https://arxiv.org/abs/2611.25670)): quantizes latent
  chain-of-thought VLMs whose continuous thoughts are fed back through the full model, not
  through reused internal layers.
- **Learning to Read Events for Exact State Tracking with Frozen Language Models**
  ([2611.25211](https://arxiv.org/abs/2611.25211)): a frozen language model reads each event
  and an external integer register composes them; no internal layer is reused.
- **Depth-Linked Residual Tokens for Multimodal Retrieval and Generation**
  ([2611.26752](https://arxiv.org/abs/2611.26752)): compared against looped models, but runs
  the backbone once and links appended learnable tokens with a small residual recurrence
  instead of reusing layers.
- **Loop-OPF: Solver-Informed Learning for Optimal Power Flow with Inference-Time Topology
  Adaptivity** ([2611.27013](https://arxiv.org/abs/2611.27013)): solves DC-OPF as the fixed
  point of a primal-dual (PDHG) solver iteration whose only learned parts are step-size
  parameters, which makes it a tuned solver rather than a reused learned layer.
