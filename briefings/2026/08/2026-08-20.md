# Daily Loop-Model Briefing - 2026-08-20

## Outcome

Four papers were added. Each has an explicit learned internal operator reused
within one forward process. The boundary remains strict: stage-specific iterative
networks, repeated full-model calls, and flow-based iterative inference are not
treated as loop models.

## Added

### Allocating recurrent compute (`2608.18230`)

MixerLoop asks which operators should receive recurrent compute. In every
physical layer it runs the same Gated DeltaNet mixer four times, then runs that
layer's dense FFN once. This differs from FullLoop, which repeats the whole
backbone, including every FFN.

Why it was added: the learned mixer is explicitly weight-tied across its four
applications inside the forward process. The architecture therefore moves loop
design from block level to operator level.

Reader takeaway: at 110M parameters, MixerLoop retains 41.5% of FullLoop's CORE
gain over NoLoop while using 45.9% fewer recurrent-backbone projection FLOPs and
reaching up to 1.52x FullLoop prefill throughput. It is a cheaper intermediate
compute-quality point, not a universal replacement: FullLoop remains better on
110M CORE, manipulation, and held-out NLL.

### Safe test-time depth (`2608.18222`)

This analysis writes a recurrent-depth reasoner as repeated application of one
learned operator and classifies its dynamics as settling, marginal, or drifting.
It derives a decoder-margin condition under which additional recurrent steps
cannot change a correct decoded answer.

Why it was added: the paper directly analyzes weight-tied recurrent-depth
families and tests interventions on their training objectives.

Reader takeaway: a terminal fixed-point objective causally changes whether
models settle and extrapolate to additional depth. On unseen Sudoku difficulty,
exact match rises from 0.19 to 0.34 with added depth; across a 304-run campaign,
all 19 extrapolating constraint-propagation runs are non-drifting. Huginn-3.5B is
diagnosed as non-settling, so weight tying alone does not ensure safe inference.

### Compositional tool calling (`2608.18171`)

The paper evaluates both Ouro and retrofitted language models that place a
shared recurrent block between fixed prelude and coda layers. That block is
reused multiple times before the next-token prediction.

Why it was added: its application study is built around explicit recurrent-depth
weight sharing, rather than repeated prompting or agent turns.

Reader takeaway: the gains concentrate on multi-call and dependency-aware tool
use. In the controlled BFCL retrofit, overall accuracy rises from 39.1 to 41.8
for OLMo-2-1B and from 21.4 to 32.9 for Llama-3.2-1B. Adaptive stopping can match
the best fixed-depth operating point with fewer average iterations, although the
paper does not provide one universal stopping threshold.

### SABET-QA (`2608.20083`)

SABET-QA refines temporal knowledge-graph states over four hops. The hop-specific
projection is untied, but every hop reuses the same learned memory update,
attention, gating, and entity/time scoring modules.

Why it was added: the strict scope only requires some learned internal operator
to be reused, and the shared memory update is explicitly called inside the
single-forward hop loop.

Reader takeaway: increasing the hop count from one to four improves complex-query
Hits@1 on Complex-CronQuestions from 0.439 to 0.524. The hard-supervision variant
reports Hits@1 of 0.954 on CronQuestions and 0.807 on Complex-CronQuestions, but
the evidence remains concentrated in temporal knowledge-graph benchmarks.

## Near misses

- **Iterative Proxy Correction** (`2608.19971`) uses separately parameterized
  mappings at each correction stage, so reuse of a learned stage operator is not
  established.
- **Scaffolding Minds** (`2608.19669`) learns latent visual targets and an RL
  sampler, but does not repeat a learned internal layer within one forward pass.
- **Boundary Refinement** (`2608.19553`) invokes a frozen grounding model in a
  second high-resolution pass. That is a repeated full-model call.
- **3D-CurvSegFlow** (`2608.19965`) uses progressive flow-matching inference,
  which is outside the collection's diffusion/energy/flow boundary.
